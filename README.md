# Finance Intelligence — Interactive Demonstration

A browser-based executive finance workspace with simulated sources, adjustable expenses, an explainable KPI-design assistant, reconciliation review, configurable board reporting and detailed workflow modules. No real financial systems are connected.

**Open the demo:** https://sastree14.github.io/AI-Demonstration/

## Executive CFO workspace (default home page)

The default page is designed around a finance director's work: period, entity and product-line filters; revenue/EBITDA/budget/cash indicators; synthetic record views; local expense adjustments; guided KPI formula proposals with explicit confirmation; a simulated bank-vs-ledger discrepancy requiring an explanatory review note; and a configurable board pack. In **Board pack**, use **Print / Save PDF** and choose "Save as PDF" in the browser print dialog.

The KPI assistant is a **deterministic, rules-based simulation**, not an LLM or an autonomous code editor. Saved KPI definitions, review notes and manual adjustments remain in this browser's local storage; no Python files, live accounts or source systems are modified. The product dimension is an explicitly synthetic allocation of aggregate financial data, not authentic product-level transactions.

The original more detailed experience remains available through **Explore detailed system capabilities** in the footer of the same demo. There is no navigation to unrelated client demonstrations.

## Detailed system capabilities

The optional **Workflow guide · 4 steps** explains the complete process:

1. **Collect:** spreadsheet and general-ledger inputs.
2. **Validate:** reconcile sources and flag an exception.
3. **Calculate:** compute indicators and assemble a report.
4. **Review:** inspect the record and simulate an approval.

In each stage, the interface distinguishes **deterministic automation** from **optional AI assistance**. Use the existing modules to inspect actual simulated settings and results. **System capabilities & settings** covers further configurations and technical controls.

The rest of the workspace includes:

- **Executive overview** — selected KPI values and charts.
- **Data foundations** — origin references, local CSV loading, reconciliation check.
- **Finance automation** — adjustable task schedule, sample runs, timeline and review queue.
- **Quantitative intelligence** — what-if inputs and controlled custom KPI expressions.
- **Board pack studio** — reporting period, narrative tone, section selection and Print / Save PDF.
- **Agent workspace** — scripted questions about provenance, timings, formulas and permissions.
- **Access & governance** — persona-based visibility demonstration and permission matrix.
- **Integrations** — illustrations for ERP, CRM, database and BI connectivity.
- **System capabilities & settings** — searchable information on additional functions, security and configuration requirements.

A step-by-step description is available in [Functional demonstration guide](docs/WORKFLOW_GUIDE.md).

## Run locally

Requirements: Node.js 20.9+ (22 recommended).

```bash
npm install
npm run dev
```

Open `http://localhost:3000`. Build checks:

```bash
npm run typecheck
npm run build
```

The application exports a static site to `out/` and is published through the GitHub Pages workflow. No API keys or paid services are needed.

## Simulated-versus-real boundaries

- All entities, records, people, financial values, errors and run histories are **fictional**.
- Role switching is **not authentication**. In production, read and write permissions must be enforced in the backend and on the connected data source.
- Chat answers are **scripted**, not generated by a model. No OpenAI API or Agents SDK is running.
- Schedules, configuration and approvals are stored locally in the browser, not in a database or real job scheduler.
- Acknowledging a discrepancy in this example does not perform a reconciliation or correct records.
- CSV imports stay in the browser. The example does not parse `.xlsx` files.
- Connectors and embedded BI panels are **illustrative**, not connected.
- The Print / Save PDF action uses the browser print dialog.

A connected system would require approved integration architecture, company authentication, scoped data access, persistent workers, traceable source-to-result records, safe formulas, secure document handling, audit retention, authorisation and operational testing.
